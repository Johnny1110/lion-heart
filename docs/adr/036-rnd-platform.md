# ADR 036: 自研平台的形狀 —— 獨立節點分析當 golden，取代 codegen 與 SPICE 工具鏈

狀態：**已採納（2026-07-29）**
關聯：`docs/tone_revolution/phase/08-rnd-platform.md`（來源計畫）、
PRD 035（驗證 harness + 判別套件 + 食譜 + 擬合工具）、PRD 036（`mane`，自研範例踏板）、
**ADR 032**（WDF 可組合框架——本 ADR 有一半是它的後果）、ADR 033（元件參數政策）、
ADR 035（單端口/多端口的界線）
影響範圍：新增 `lh_dsp::testutil::{netlist, whitebox}`、`crates/lh-dsp/tests/whitebox.rs`、
`tools/fit_device.py`、`docs/tone_revolution/cookbook.md`；**推翻計畫 §2.1 與 §2.2 的形式**

## Context

Phase 08 是計畫的收官，命中的是目標 **#3：框架要支撐使用者自研踏板**。
計畫開出五項產出，但它是在 Phase 03 之前寫的，而 Phase 03 換掉了它的地基。

### 計畫要的東西，與現實的落差

| 計畫 | 現況 | 為什麼 |
| ---- | ---- | ------ |
| §2.1 `tools/wdf_codegen/` 跑 R-Solver 產生**符號散射矩陣**，netlist 存 `tools/netlists/` | **無物可產** | **ADR 032** 把「符號 codegen（硬前置）」與「執行期數值構造（後備）」對調了。矩陣現在由 junction 自己的 netlist 在 `calc_impedance()` 裡數值解出來，而那個 netlist 是 Rust（`JEl` / `Junction`）。沒有中間產物，也就沒有 codegen 步驟 |
| §2.2 `sim/<pedal>/` LTSpice 原理圖 + ngspice 暫態 → Python 擬合 | **沒有 ngspice**，也不該有 | Phase 02 早已把它的 ngspice fixtures 換成本專案自己的節點分析 oracle。再引入一個外部模擬器當 CI 相依，是把已經解決的問題重新打開 |
| §2.3 驗證 harness（golden vs 高精度數值電路解） | **完全可做，而且是剩下最有價值的一項** | — |
| §2.4 食譜 | 可做，但要重寫成「沒有 codegen 步驟」的版本 | — |
| §2.6 自研範例踏板 | 可做 | — |

計畫自己其實預告了這件事：§6「風險與備註」把 R-Solver 相依列為風險，並指定
「後備＝數值 S 構造」。**後備成了主線**，於是依賴它的那條工具鏈整條蒸發。

### 真正的問題

拿掉 codegen 之後，「自研平台」缺的到底是什麼？不是產生程式碼的工具——
`blocks::wdf` 已經讓一棵樹是十幾行 Rust。缺的是**知道自己做對了沒有**。

現有的測試回答不了這件事。整個 drive 家族的測試是**特性測試**：有中頻隆起、
有偶次諧波、膝部隨頻率移動、預設旋鈕落在 unity。這些全部是**一個錯得很像的
電路也會通過**的敘述。真正需要被檢查的那句話——「這棵 WDF 樹解的是這張電路圖」
——在 Phase 08 之前沒有任何測試在檢查。

## Decision

### 1. 平台的核心是**第二個求解器**，不是 codegen

新增 `lh_dsp::testutil::netlist`：一個獨立的**修正節點分析**（MNA）求解器，
與 `blocks::wdf` **不共用任何程式碼、公式或常數**。元件是 `El` 列舉（R / C /
受控源 / 二極體對 / 非對稱堆疊 / 驅動源），電容走梯形伴隨模型，非線性在目前
猜測處線性化，整個系統用阻尼 Newton 重解到不動為止。

**關鍵性質**：兩邊用的是**同一種離散化**（梯形＝雙線性），所以它們是**同一個
離散系統**的兩種寫法，不是同一個連續系統的兩種近似。因此該對到算術精度，
而殘差是可歸因的而不是隨便的：

| 比對 | 殘差 | 殘差是什麼 |
| ---- | ---- | ---------- |
| 串並聯樹，靜態轉移曲線 | 2.5e-7 V | `f32` 的底 |
| 串並聯樹，動態（Newton root） | 1.5e-7 V | 同上 |
| 串並聯樹，動態（**omega 閉式** root） | 2.1e-4 V | Wright omega 的近似誤差，**是樹本身的 1400 倍** |
| R-type junction，靜態掃描 | 相對 3.2e-5 | `f32` 在條件數幾百的散射解裡 |

最後一列是本 ADR 最想留下的數字之一：junction 的元件值跨七個數量級
（`Ri` = 1 GΩ 旁邊 `Ro` = 100 Ω），條件數就上去了。3.2e-5 相當於 −90 dB，
聽不到，但它是**任何對照的精度上限**——比這更嚴的容差是在測浮點數不是測電路。
這也直接產生了一條元件政策（§3）。

**驗收對象是 R-type**。它是整個框架裡唯一沒有封閉式可以核對的部分：
ADR 032 決定矩陣在執行期由 netlist 數值構造，正是為了「沒有東西可以抄錯」，
但那句話在 Phase 08 之前只是設計論證。現在有一條測試把它變成量測
（`the_op_amp_junction_solves_the_same_static_curve_as_nodal_analysis`）。

### 2. 判別套件放進 `testutil`，不是放進 `tests/`

新增 `lh_dsp::testutil::whitebox`：`memory` / `knee_shift` / `harmonics` /
`bounded` / `silent` / `static_curve`。餵一個 `FnMut(f32) -> f32`，回一個數字。

**兩個模組都放在函式庫裡而不是 `tests/`**，因為整合測試的模組到不了 `src/`。
使用者自研踏板時，單元測試就寫在 `src/drive/mypedal.rs` 裡；平台工具必須在
那裡拿得到。既有的 `testutil` 已經是公開的離線測試支援面（`sine`、`rms`、
`process_in_blocks`），這是它自然的延伸。

`memory` 值得單獨記一筆，因為它是**唯一一個能把白箱與 memoryless 分開的
單一數字**：memoryless 波形整形是一個函數 `y = f(x)`，同一個 `x` 必須給同一個
`y`；有電抗的電路根本不是 `x` 的函數。實作上有一個非顯然的細節——分桶之後
**要先擬合二次式再看殘差**。只減線性項會把曲線的曲率算成記憶（`tanh` 在
1/128 寬的桶裡就有 2e-4，足以蓋過一個弱電抗電路）；減掉二次項之後底降到
3.4e-6，而電路讀到 0.05 以上（`mane` 1.52）。四個數量級的分離。

### 3. `f32` 條件數是一條**元件參數政策**，不只是一個測量值

§1 那個 3.2e-5 有直接後果：JFET 輸入 op-amp 的 datasheet `Ri` 是 1e12 Ω，
但在這個 junction 裡 1e12 與 1e9 **不可分辨**（兩者都遠大於其他所有阻抗），
而 1e12 會把散射解的條件數推到 `f32` 撐不住。

**決策**：`Ri` 取「足夠大」而非 datasheet 的字面值，並在常數旁寫明理由。
這不是推翻 ADR 033（op-amp 參數來自 datasheet），是替它補一條邊界：
**datasheet 是來源，數值條件是約束**；當一個參數已經飽和到不影響結果時，
取讓求解器健康的那個值，並把它記下來。`mane` 的 `RI` 常數就是這樣寫的。

### 4. SPICE 擬合流程 → **器件級**擬合工具

`tools/fit_device.py`（numpy + scipy，無 SPICE）：從 datasheet 的 I–V 點擬出
`(Is, n)`，輸出可直接貼進踏板二極體表的 Rust 常數。

兩個實作決定值得記：

- **在 log 電流上做最小平方**，不是在安培上。用安培的話，一個 10 mA 的點會壓過
  1 mA 以下所有點的總和，而吉他削波器待的地方恰恰是膝部而不是硬導通區。
- **`Is` 在 log 空間擬合**。它在本專案關心的器件之間跨十幾個數量級
  （LED 1e-16、鍺 1e-7），線性參數會讓求解器在小端爬不動。

**沒做的**：電路級的 SPICE 對照。理由是 §1 的 harness 在同一個位置做得更好
——它在 CI 裡跑、不需要外部執行檔、而且因為共用離散化所以容差有意義。

### 5. 食譜（`docs/tone_revolution/cookbook.md`）與範例踏板

食譜的驗收標準是「別人照著走得完」，所以它從**第 0 步：這顆該不該用 WDF**
開始（ADR 035 的界線），而不是從拼樹開始——那一步錯了後面全白做。

範例踏板 **`mane`**（PRD 036）照食譜從零走完：**沒有新增任何 junction、任何
adaptor、任何 root**。那句「框架已經足以拿來設計，不只是拿來移植」因此是
可查證的，而不是宣稱。

## Consequences

**好的**

- 「這棵樹解的是這張圖嗎」第一次有了答案，而且是量化的答案。ADR 032 那個
  「矩陣從拓撲導出所以不會漂」的設計論證，現在有測試背書。
- 殘差**可歸因**是意外的收穫：閉式 root 的誤差比樹大 1400 倍，這件事現在被
  一條測試釘著（`the_closed_form_root_is_the_dominant_error_not_the_tree`）。
  將來若有人動了 `omega`，這條會先叫。
- 判別套件把每顆踏板各自重推的量測收成一份。新踏板繼承而不是重寫。
- 使用者要加一顆自己的踏板，路徑是一份文件加兩個 `testutil` 模組，全部在
  repo 裡，不需要裝任何東西。

**要付的**

- `testutil` 進了函式庫，所以 `netlist`/`whitebox` 會被編進 `lh-dsp`。它們是
  `Vec`-based、`f64`、會配置記憶體的離線程式碼，**永遠不可以從音訊路徑呼叫**。
  兩個模組的檔頭都寫了這句話，但這是一條靠紀律維持的界線。
- harness 的電路是在測試裡**宣告**的（同一組常數同時建 WDF 樹與 netlist），
  所以它驗證的是**框架與拓撲**，不是「某個 `drive/*.rs` 有沒有把 schematic
  抄對」。後者仍然是各踏板自己的手解 AC 分析的工作。這個界線寫在
  `tests/whitebox.rs` 的檔頭。
- 沒有 SPICE，就沒有「對照 LTSpice 暫態」這條路。若日後真的需要（例如驗證一顆
  本專案沒有模型的器件），要重新評估。

**沒做的（相對於計畫）**

- **沒有 `tools/wdf_codegen/`、沒有 `tools/netlists/`**（§2.1，ADR 032 已作廢）。
- **沒有 `sim/<pedal>/` 與 ngspice 流程**（§2.2，改為器件級擬合）。
- **沒有 tweakable component 設計模式**（§2.5，選配）。`diode-clipper`（PRD 030）
  已經是這個想法的踏板版本——一顆二極體四種接法，器件與數量都上面板；再做一個
  通用的「掃任意元件值」模式需要 GUI 管線，價值與成本不成比例。食譜 §3.1 改為
  說明「怎麼把一個元件值變成一顆旋鈕」（`Ctl::Trim`），那才是實際會用的形式。
- **沒有對 ZenDrive 的 MOSFET 重跑擬合**（計畫 §4 的驗收項）。**ADR 034 已經
  處理完這件事**：那次擬合是在 Phase 04 做的，理由也已經更正過（不是因為 BYOD
  的 P1/P3 接線 bug 污染了參數，而是「擬合 `Is·sinh`、求值 `2·Is·sinh`」）。
  重跑一次不會產生新資訊。
