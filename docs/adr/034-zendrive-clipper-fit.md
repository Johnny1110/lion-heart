# ADR 034: ZenDrive 削波器參數自行擬合 — 兼修正計畫對 BYOD 擬合值的判讀

狀態：**已採納（2026-07-28）**
關聯：`docs/tone_revolution/phase/04-opamp-overdrive-family.md` §2.2（來源計畫）、
PRD 027（`zendrive` 落地規格）、ADR 033（op-amp 參數與二極體選單政策）、
ADR 032（WDF 框架）
影響範圍：`drive::zendrive`；並**修正 Tone Revolution 計畫 v2 深審的一項判讀**

## Context

計畫 §2.2 對 ZenDrive 下了兩個並列的結論，並據此指示「二極體參數**不抄 BYOD**」：

1. BYOD 的 `zen_drive` 把二極體對的阻抗參考掛在 **P1**（輸入級，port 阻抗約 5 Ω），
   波卻與 **P3**（回授節點，約 20 kΩ）交換——對照同專案 TS 的 `dp { P3, ... }`，
   幾乎確定是複製貼上 bug。
2. 因此其擬合參數 `Is ≈ 5.241e-10`、`nVt ≈ 0.0787`（物理 `Vt` 的 ~3 倍）是
   「**繞著這個 bug 擬合出來的**」，`nVt` 反常就是證據。

第 1 點成立。**第 2 點不成立**，而且第一顆需要它的踏板落地時才查得出來。

## Decision

### 1. 修正：那組擬合值沒有被 bug 汙染，`nVt` 反常另有解釋

證據在 BYOD 自己的 `sim/ZenDrive/`：

- `ZenClipper.asc` 是一份**獨立的** LTspice 削波器電路——電壓源串 200 Ω 推一組
  反並聯支路，量測跨壓與電流。**與踏板電路無關**，更與 P1/P3 的接線無關。
- `zen_clipper.py` 對那份掃描做 `curve_fit`。

也就是說，擬合是**離線、對著單獨的削波器曲線**做的，不是在電路裡憑耳朵調的。
bug 不可能參與其中。

`nVt` 為什麼是 ~3 倍？看 `.asc` 就知道：每條支路是 **1N4148 串一顆二極體接法的
2N7002 MOSFET**，兩顆元件疊在一起。兩個接面串聯，斜率自然約兩倍，再加上 MOSFET
平方律膝部的柔和度——**完全物理，不是補償**。

計畫該處的推論是合理的猜測，但事實不同；照 CLAUDE.md「若程式與文件不符就標記出來」
的規矩記在這裡，並在 phase 04 的落差方框註明。

### 2. 仍然自行擬合，理由改成一個**可量測**的：那組值有 2× 不一致

`zen_clipper.py` 擬合的模型是 `i = Is·sinh(v/Vt)`（**單一** `Is`），但
`DiodePairT` 執行期算的是 `i = 2·Is·sinh(v/nVt)`。同一組數字餵進兩倍電流的模型，
削波點就會偏低——量出來是**整個工作範圍低 60–105 mV**，與 `nVt·ln 2 ≈ 55 mV` 的
預期同量級。

本專案改為**自行對同一條曲線擬合 `2·Is·sinh` 模型**（本次工作階段內做的最小平方，
對數電流域，取電路實際工作的 1 µA–300 µA）：

```
IS        = 7.50e-11 A
THERMAL_V = 0.0729 V      (整個 1N4148+2N7002 疊層的 n·Vt，不是單一接面的 ideality)
```

對照曲線四個取樣點（1 µA / 10 µA / 100 µA / 1 mA），誤差 **−8 / +15 / +7 / −4 mV**；
BYOD 那組同樣算法下是 **−105 / −68 / −62 / −60 mV**。
`the_clipper_matches_the_fitted_device_curve` 把這件事釘住，並且同時釘住「膝部比矽
高 ≥ 0.35 V、每十倍電流的斜率比矽緩 ≥ 1.3 倍」——那兩個數字就是這顆踏板「透明」的
物理來源。

**拓撲事實**（元件與接法查自 `.asc`，屬 CLAUDE.md 允許的「事實」）：反並聯兩支，
每支 = 1N4148 串二極體接法 2N7002。**曲線資料是模擬輸出，不是程式碼**；本專案只用
它當量測值，擬合與模型都是自己的。

### 3. 接線 bug 照修

二極體面對 **P3**（回授節點）。`a = v + R·i(v)` 裡的 `R` 差 3,600 倍不是小事——
用 5 Ω 幾乎等於不削波。

### 4. 4.5 V 偏壓不建模

BYOD 把 `R4` 與 `R5_R6_C5` 接到 4.5 V 軌（單電源踏板的 Vcc/2），並在 `prepare` 裡
空跑 20,000 個 sample 等暫態穩定。

本專案**以 0 V 為參考**，不建這條偏壓。理由：我們的 op-amp 模型沒有電源軌，所以
4.5 V 在訊號路徑上是純共模——它只在輸出產生一個直流偏移（真實踏板由輸出電容擋掉、
這裡由 `post()` 的 DC blocker 擋掉），對削波**完全沒有影響**（虛短讓回授兩端同電位，
二極體看到的直流是 0）。建了它只換來一段要空跑掉的開機暫態。這正是計畫 §3
非目標所允許的簡化（「不做整顆踏板每一級」）。

如果日後真要做電源軌削頂（supply clipping），這條偏壓就必須補回來——屆時
`ResistiveVoltageSource` / `CapacitiveVoltageSource` 都已經在框架裡了。

## Consequences

**好的**

- 削波器參數有一條可重跑的來源：拓撲來自公開電路，數值來自對該電路曲線的擬合，
  誤差有測試釘住。不是「抄來的常數」，也不是「憑感覺調的」。
- 計畫裡一項錯誤判讀被更正，且更正的理由留在這裡，下一個讀計畫的人不會再被誤導。
- 「BYOD 值只當起點」這條政策第一次被**具體執行**，而且執行的結論比原本預期更細緻：
  bug 是真的、擬合值不可直接用也是真的，但**原因與計畫寫的不同**。

**要付的**

- `THERMAL_V` 是一個疊層的等效熱電壓，不是任何單一元件的 ideality；`DiodePair` 的
  API 以 `(is, n, vt)` 收參數，所以這裡寫成 `THERMAL_V / VT` 當 `n`。讀起來需要註解
  才不會誤會成「ideality = 2.8」。
- 曲線擬合只在 1 µA–300 µA 有保證。狂推到 mA 級以上時模型會漂（1 mA 處仍在 4 mV
  內，再高就沒驗過）。實務上電路到不了那裡。
- **不建偏壓 = 不會有電源軌不對稱削波**。ZenDrive 本來就不靠那個發聲，但若日後想做
  「電池沒電」那類效果，得先補回偏壓。

**沒做的**

- 沒有移植 BYOD 任何程式碼（GPL-3）。
- 沒有用 BYOD 的擬合結果，只用了它的電路圖與模擬輸出當量測事實。
- 沒有建 MOSFET 的平方律 / 次臨界模型——`DiodePair` 是指數對，疊層以等效斜率表示。
  真要做器件級 MOSFET root 是 Phase 08 的題目。
